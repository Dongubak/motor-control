## 1. 방향 확인: Z축 방향과 모터 회전 방향

### 코드에서 방향 추적

`motor_csv.py` 내부 처리 흐름:

```
move_to_position_mm(+600)          ← 양수 = 아래로 이동
    → target_pulse = +음수(負) 절대값 펄스
    → TrapezoidalProfile._dir = +1  (distance > 0)
    → get_velocity() 반환값 = 양수(正)
    → 드라이브로 양수 속도 명령 전송 → 정방향(CCW) 회전 → Z 하강(↓)

move_to_position_mm(-600)          ← 음수 = 위로 이동
    → TrapezoidalProfile._dir = -1
    → 음수 속도 명령 → 역방향(CW) 회전 → Z 상승(↑)
```

### 방향 정리표

| 동작 | 명령 부호 | 드라이브 속도 | 회전 방향 | 리미트 신호 |
|------|----------|-------------|---------|-----------|
| Z 하강 (아래↓) | 양수 (+mm) | 양수 | **정방향 CCW** | POT (하단 리미트) |
| Z 상승 (위↑) | 음수 (−mm) | 음수 | **역방향 CW** | NOT (상단 리미트) |

> **iX7NH 드라이버 규정**: 정방향 = CCW(Counter Clock-Wise), 역방향 = CW(Clock-Wise)
> (PDF p.183 속도 프로파일 도표 기준)

## 2. 리미트 스위치 및 I/O 핀 구성

### I/O 커넥터 핀 할당 (PDF p.127)

| 핀번호 | 신호명 | 기본 할당 | 기능 | Z축에서의 역할 |
|-------|-------|---------|------|--------------|
| **11** | DI1 | **POT** | 정방향(CCW) 회전금지 | **하단 리미트 + 원점 기준** ← Homing 방향 |
| **12** | DI2 | **NOT** | 역방향(CW) 회전금지 | 상단 안전 리미트 (과주행 방지 전용) |
| **7** | DI3 | **HOME** | 원점 센서 | (선택) 별도 원점 스위치 |

### 스위치 배치

```
  ┌──────────────────────────────────┐
  │          갠트리 Z축 컬럼           │
  │                                  │
  │  ▲ [상단 리미트 스위치]             │ ← NOT (DI2, Pin 12)
  │  │  역방향(CW) 한계 / 안전 정지용   │   과주행 방지 전용 (Homing과 무관)
  │  │                               │
  │  │  < 작업 영역 >                 │
  │  │                               │
  │  ▼ [하단 리미트 스위치]  ★ 원점    │ ← POT (DI1, Pin 11)
  │     정방향(CCW) 한계              │   Homing 탐색 기준 + 하단 안전 리미트
  └──────────────────────────────────┘
```

## 3. 리미트 스위치 단자 구성 및 배선

### 사용하는 스위치 단자

본 프로젝트에서 사용하는 리미트 스위치는 **COM, NC, NO** 세 단자 중 **NO와 COM만 외부 배선 가능**하다.

| 단자 | 설명 | 사용 여부 |
|-----|------|---------|
| COM | 공통 단자 | ✅ 사용 |
| NC | Normal Closed (평상시 연결) | ❌ 외부 접속 불가 |
| NO | Normal Open (평상시 개방) | ✅ 사용 |

### 배선 방법: NO → +24V, COM → DI 핀

```
드라이브 I/O 커넥터           리미트 스위치
                             ┌─────────────┐
  Pin 6 (+24V) ─────────────►│ NO          │
                             │             │
  Pin 11 (DI1/POT) ◄─────────│ COM         │  (하단 스위치)
                             └─────────────┘

  Pin 6 (+24V) ─────────────►│ NO          │
                             │             │
  Pin 12 (DI2/NOT) ◄─────────│ COM         │  (상단 스위치)
                             └─────────────┘
```

### 신호 논리 동작

| 스위치 상태 | NO-COM 회로 | DI 핀 전압 | 드라이브 해석 | 결과 |
|-----------|-----------|-----------|------------|------|
| 평상시 (미접촉) | **OPEN** (개방) | **0V** | 리미트 비활성 → 이동 허용 | 정상 운전 |
| 작동 시 (접촉) | **CLOSED** (연결) | **24V** | 리미트 활성 → 정지 명령 | 모터 정지 |
| 케이블 단선 | OPEN (단선) | **0V** | 리미트 비활성으로 오인 | ⚠️ 정지 안 됨 |

> **NO 배선의 주의사항**: 케이블이 단선되면 스위치 미감지 상태와 구분이 안 된다.
> 갠트리 같은 중량물에서는 케이블 경로 보호(금속 덕트, 체인 케이블 캐리어 등)를 통해
> 단선 리스크를 최소화해야 한다.

## 4. Homing Method 선택

원점 = **Z축 맨 아래(정방향 끝)** 이므로 Homing 초기 이동방향은 **정방향(CCW, 아래↓)**.

### 후보 방법 비교

| Method | 초기 이동방향 | 원점 기준 신호 | 적합성 | 비고 |
|--------|------------|-------------|------|------|
| **2** | 정방향(CCW)↓ | POT + Index(Z) 펄스 | ✅ 권장 | 엔코더 Z상 배선 필요, 가장 정밀 |
| **-4** | 정방향(CCW)↓ | Positive Stopper (기계적 충돌) | ⚠️ 비권장 | 반복 충격으로 기구부 손상 위험 |
| **-6** | 정방향(CCW)↓ | HOME 스위치만 (POT 만나면 에러) | ✅ 대안 | 하단에 별도 HOME 스위치 설치 필요 |
| **24** | 정방향(CCW)↓ | HOME 스위치 (POT 만나면 방향 전환) | ✅ 대안 | 하단에 별도 HOME 스위치 설치 필요 |

### 권장: **Method 2** (POT + Index 펄스)

```
동작 시퀀스:
(A) 정방향(CCW, 아래↓)으로 "스위치 탐색 속도(0x6099:01)"로 이동
(B) 하단 리미트 스위치(POT, DI1/Pin 11) 신호 변화 감지
    → 방향 전환, 역방향(CW, 위↑)으로 "Zero 탐색 속도(0x6099:02)"로 감속
(C) 첫 번째 Index(Z) 펄스 검출 → 해당 위치를 Home으로 확정

결과: POT 스위치 근처의 Index 펄스 위치 = 원점(0mm)
```

> **Index(Z) 펄스**: 엔코더가 1회전마다 1번 출력하는 기준 펄스.
> I/O 커넥터 Pin 17/18 (ZO/ZO̅)으로 출력 가능. 드라이브 내부에서 자동 감지.
> Method 2는 매번 동일한 Index 펄스 위치에 원점 확정 → 재현성 우수.

### 대안: **Method -6** (Index 펄스 배선 불가 시)

하단에 별도의 HOME 스위치(DI3, Pin 7)를 설치하고, POT 스위치보다 위쪽(약 5~10mm)에 위치시킨다.

```
동작 시퀀스:
(A) 정방향(CCW, 아래↓)으로 스위치 탐색 속도로 이동
(B) HOME 스위치(DI3) ON 감지 → 감속 정지 → 원점 확정
    ※ 이동 중 POT(DI1)가 먼저 감지되면 Homing Error 발생 → HOME 스위치 위치 재확인 필요
```

## 5. SDO 파라미터 설정

Homing 모드 실행 전 설정해야 할 오브젝트:

| 주소 | 이름 | 권장값 (Method 2) | 단위 | 설명 |
|-----|------|-----------------|------|------|
| `0x6098` | Homing Method | **2** | - | 정방향 + POT + Index 펄스 |
| `0x6099:01` | Speed during search for switch | 10,000,000 ~ 30,000,000 | UU/s | 스위치 탐색 속도 (≈ 10~30 RPM) |
| `0x6099:02` | Speed during search for zero | 500,000 ~ 2,000,000 | UU/s | Zero 탐색 속도 (≈ 1~5 RPM) |
| `0x609A` | Homing Acceleration | 5,000,000 | UU/s² | Homing 가감속 |
| `0x607C` | Home Offset | 0 | UU | 원점 오프셋 (0 = Home 위치가 곧 Zero) |
| `0x201E` | Homing Done Behaviour | 0 | - | 완료 후 이동 없음 |

> **UU (User Unit)**: 드라이브 내부 펄스 단위.
> Z축 기준 EFFECTIVE_PPR = 16,777,216 pulse/rev.
> 30 RPM ≈ 30/60 × 16,777,216 ≈ 8,388,608 UU/s

SDO 설정 코드 예시 (Python, pysoem):

```python
import struct

def setup_homing(slave, method=2, search_speed=10_000_000, zero_speed=1_000_000, accel=5_000_000):
    slave.sdo_write(0x6098, 0, struct.pack('<b', method))          # Homing Method = 2
    slave.sdo_write(0x6099, 1, struct.pack('<I', search_speed))    # 스위치 탐색 속도
    slave.sdo_write(0x6099, 2, struct.pack('<I', zero_speed))      # Zero 탐색 속도
    slave.sdo_write(0x609A, 0, struct.pack('<I', accel))           # 가감속
    slave.sdo_write(0x607C, 0, struct.pack('<i', 0))               # Home Offset = 0
```

## 6. 하드웨어 설치 위치 지침

```
  ┌──────────────────────────────────────────────┐
  │ Z축 컬럼 (전체 스트로크 가정: 약 700mm)        │
  │                                              │
  │  ▲ 기계적 상단 끝                             │
  │  │ [상단 리미트 스위치 NOT]  ← 기계 끝에서 10mm 여유
  │  │                                          │
  │  │                                          │
  │  │       < 실제 작업 영역 >                  │
  │  │                                          │
  │  │ (선택) [HOME 스위치]  ← POT 위쪽 5~10mm   │
  │  ▼ [하단 리미트 스위치 POT]  ← 기계 끝에서 10mm 여유
  │    ↑ 이 지점 근처의 Index 펄스 = 원점(0mm)    │
  │  ▼ 기계적 하단 끝 (물리적 스토퍼)              │
  └──────────────────────────────────────────────┘
```

- **하단 리미트 (POT)**: 기계적 한계에서 **10mm 이상 여유** 확보
  - Homing 탐색 속도(≈10 RPM)에서 스위치 ON → 감속 → 방향 전환까지의 오버런 ≈ 2~3mm
- **상단 리미트 (NOT)**: 기계적 한계에서 **10mm 이상 여유** 확보
  - 안전 정지 전용. Homing과 무관
- **HOME 스위치 (선택)**: POT 스위치 위 5~10mm 지점에 설치
  - Method -6 사용 시에만 필요

## 7. Homing 모드 실행 절차

### CiA 402 Homing 실행 시퀀스

```
1. 드라이브를 Operation Enabled 상태로 전환
2. 동작 모드 변경: SDO 0x6060 = 6 (Homing Mode)
3. Homing 파라미터 SDO 설정 (0x6098, 0x6099, 0x609A)
4. Controlword bit4 = 1 → Homing 시작: 0x6040 = 0x001F
5. Statusword 모니터링 (0x6041):
   - bit12 = 1: Homing Attained (원점 확정 완료)
   - bit13 = 1: Homing Error → 즉시 정지 처리
   - bit10 = 1: Target Reached
6. 완료 후 동작 모드 복귀: SDO 0x6060 = 9 (CSV Mode)
7. 소프트웨어에서 set_origin() 호출 → 현재 위치를 소프트웨어 원점으로 동기화
```

### Statusword Homing 비트 (0x6041)

| 비트 | 이름 | 의미 |
|-----|------|------|
| bit10 | Target Reached | 이동 완료 |
| bit12 | Homing Attained | 원점 확정 완료 ← 이 비트가 1이 되면 성공 |
| bit13 | Homing Error | 오류 발생 (리미트 미감지, 타임아웃 등) |

### 소프트웨어 구현 방안

현재 코드(`motor_csv.py`)는 CSV 모드 전용이다. Homing은 드라이브 내부 Mode 6를 사용하므로 **별도 초기화 함수**로 분리하여 구현한다.

```
[권장 구현 순서]
bus.start() 이전에:
  1. SDO로 Homing 파라미터 설정
  2. Homing Mode(6)로 전환 후 실행
  3. Statusword bit12 대기 (완료 확인)
  4. CSV Mode(9)로 복귀
  5. 기존 bus.start() 및 set_origin() 호출
```

## 8. 안전 고려사항

### 두 서보모터 동기화

Z축에 두 개의 서보가 있으므로 Homing 시 **두 모터를 반드시 동시에 동일 속도로** 이동.

- 각 드라이브에 동일한 Homing 파라미터 설정
- 두 드라이브의 `0x6040 bit4`를 동시에 SET하여 동기 시작
- Homing 중 Cross Coupling 미사용 → 두 모터의 실제 위치 차이를 EtherCAT 사이클 내에서 직접 모니터링 필요

### 속도 설정 지침

| 단계 | 권장 속도 | 비고 |
|-----|---------|------|
| 스위치 탐색 (0x6099:01) | **10~30 RPM** | 오버런 최소화, 스위치 감지 확실성 |
| Zero 탐색 (0x6099:02) | **1~5 RPM** | Index 펄스 정밀 검출 |

### Homing 실패 처리

- `bit13 = 1` (Homing Error) → 즉시 양쪽 모터 속도 0 명령 후 에러 보고
- 지정 시간(예: 60초) 내 bit12 미감지 → 타임아웃 에러로 처리
- POT 스위치 배선 점검 방법: 드라이브 파라미터 모니터링에서 DI1 상태 확인
